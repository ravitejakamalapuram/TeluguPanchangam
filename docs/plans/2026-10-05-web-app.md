# Telugu Panchangam on the web (desktop and mobile)

Status: proposed, waiting for approval. Companion to `2026-10-05-whatsapp-rashi-card.md`.

## Bet

The website becomes the main product and the Chrome extension becomes one way to open it. Most Telugu users
can't or won't install an extension; they arrive from a WhatsApp forward or a Google search like
"ఈ రోజు పంచాంగం" or "mesha rasi phalalu today", on a phone or a desktop. The web app gives every one of them
the full experience: today's panchangam, the monthly calendar, festivals, rashi phalalu, sankalpam,
reminders, print view, Gita verse and sharing.

| Surface | Who | Status |
|---|---|---|
| Website, responsive (desktop and mobile), installable as an app | Everyone, from WhatsApp and search | This plan |
| Chrome extension (new tab) | Desktop users who want it on every tab | Live, 2.0.0, same UI |
| Android app (a wrapper around the website) | Users who want an icon and a morning notification | Later, only with traction |

## The key finding: the full web view already exists in code

`newtab.html` already runs outside the extension. `storage-shim.js` swaps `chrome.storage.local` for
`localStorage` when there is no extension, and `chrome.storage.local` is the only extension API the UI uses
(`newtab.js`, `i18n.js`, `reminders.js`, `print.js`, `ui/onboarding.js`, `ui/rating.js`). `core/` and
`lib/astronomy.js` are plain ES modules. `newtab.css` already has breakpoints at 1200px and 600px.

So the web app is not a rewrite. The same HTML, CSS and JS are deployed as a website, with a thin web shell
around them. One codebase serves both, so a fix or feature lands on the web and in the extension together.
This matches the project rule of no duplicated code.

## What we build

1. **Web shell (`web/`):** `index.html` that loads the same UI, a PWA manifest and service worker (installable,
   works offline), `robots.txt`, `sitemap.xml`, Open Graph tags so WhatsApp previews look right, and a
   one-line "Get it on every new tab" banner shown only on desktop Chrome.
2. **Mobile polish:** the new tab was designed for wide screens. Audit it at 360px wide: a bottom bar for
   Today, Calendar, Rashi and More; bigger tap targets; the calendar grid as swipeable months. These are CSS
   and small layout changes in the shared files, so the extension gets them too.
3. **One-tap WhatsApp share:** on phones the Web Share API hands the card image straight to WhatsApp; where
   that isn't available, a `wa.me` link shares text plus the page link. The same button covers the
   panchangam card and the rashi card.
4. **Search pages, built ahead of time:** a Node build runs the engine and writes plain HTML that Google
   reads without JavaScript: `/YYYY/MM/DD/` for each day a year ahead, `/rasi/<name>/` for 12 rashis,
   `/festivals/<name>-YYYY/` for each festival, and `/month/YYYY-MM/` printable calendars. That's about 500
   pages a year. Each page opens into the full app.
5. **Extension-only bits stay out of the web:** the new-tab override and the "keep this new tab" note are
   skipped when the page isn't running as the extension.

## Repository layout

The web shell and its build live in `web/` in this repo, importing the shared files from the root. The
extension's `release.yaml` uses an allowlist, so nothing in `web/` reaches the Chrome Web Store zip. If the
shared UI later needs to move into its own folder (for example `app/`), that is a separate refactor PR with
no behaviour change.

## Hosting and domain

GitHub Pages, deployed by a `pages.yml` workflow copied from `app-template-web`. Web apps deploy straight to
Pages, not through release-platform, as that template decided. A nightly scheduled run rebuilds the search
pages; it is seconds of Node, so it fits the "no costly CI jobs" rule.

Recommend a short `.in` domain (about ₹700 to ₹900 a year) instead of `ravitejakamalapuram.github.io/...`:
people type and trust it, and WhatsApp previews show it. This is the only recurring cost.

## Money

The extension can't carry ads, but a website can. In order:

1. **Ads (AdSense):** one unit below the fold on day, rashi and festival pages, never inside the app view or
   on share cards. Apply only after traffic is steady, because AdSense needs real content and visits.
2. **Sponsored line on festival pages** (temples, jewellers, puja stores), sold directly once pages rank.
3. **Personal reading** (nakshatra-based tara balam, muhurtham alerts) as the paid tier from the WhatsApp
   plan, sold on the web where payment is easy.

## Phases

| Phase | Build | Gate to the next phase |
|---|---|---|
| 1. Full app on the web (about 1 week) | Web shell, PWA, Pages deploy, domain, WhatsApp share on phones, extension-only bits hidden | Site live and the shared UI passes the existing tests in both modes |
| 2. Mobile polish (about 1 week) | 360px audit, bottom bar, tap targets, swipeable calendar | 1,000 visits in the first 4 weeks, mostly from WhatsApp |
| 3. Search pages (about 1 week) | Prebuilt day, rashi, festival and month pages, sitemap, Search Console | 5,000 search visits a month |
| 4. Earn | AdSense, then a direct sponsor slot on festival pages | Revenue covers the domain and then some |
| 5. Android app | Play Store wrapper (Trusted Web Activity) with a morning notification | Only if repeat visitors are over 20% |

## Measure

Cookie-free analytics (Cloudflare Web Analytics, free), so there is no consent banner and nothing personal is
stored. Track visits by source (`utm_source=whatsapp` on shared links), device type, shares, app installs,
and Search Console clicks per page type.

## Privacy

Same rule as the extension: location is optional and stays on the device, settings and reminders live in
`localStorage`, and no personal data leaves the device. The privacy policy gets a web section before launch.

## Risks

- **Shared UI breaks one surface:** run the existing test suite against both the extension and the web
  build in CI.
- **Search competition** from large panchangam and news sites: our edge is speed, Telugu-first text,
  city-accurate timings and WhatsApp sharing, so measure before investing in more page types.
- **Two places to see the same thing** may split extension installs: the desktop banner points web visitors
  to the extension, and the extension links to the website for phone sharing.
